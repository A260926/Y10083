# 事件证据拼图（Event Evidence Puzzle）

故障响应小组的本地事件证据拼图工具：把来自多个服务的日志、trace 片段与人工记录
放进同一时间线。**任何自动校时与关联都可解释、可复现、可重放。**

## 安装与运行

```bash
npm install
npm test -- --run
npm run dev -- --host 127.0.0.1 --port 5213
```

打开 http://127.0.0.1:5213/ ，页面标题为「事件证据拼图」，首次启动自动安装预置示例
（跨午夜墙钟、一次时钟跳变、一个内容冲突的事件 ID、重复来源收据与坏行）。
顶部下拉框可在两个时间线修订之间切换：**原始事件摘要永不改变**，只有校正视图变化。

## 数据模型与不变量

- **原始字节永久保留**：每条输入的原始文本、来源、接收时间、SHA-256 摘要存入 `raw_archive`。
- **坏行隔离**：NDJSON 逐行解析，合法事件照常入库，坏行（JSON 错误/缺 id/时间无法解析）
  进入 `quarantine`，同一坏行重复导入不产生重复隔离记录。
- **重复收据合并**：事件 ID 相同且内容摘要一致时，只追加来源收据（source/接收时间/行号/原始摘要）。
- **内容冲突**：事件 ID 相同但规范化内容摘要不同时，事件被标记 `conflict`，所有变体保留在 `event_variants`。
- **时间线修订不可变**：锚点集合经规范化哈希生成修订；改锚点只追加新修订（`parentId` 链），
  旧修订及其排序永远可重放。修订带算法版本 `piecewise-offset-v1` 与所用锚点集合。
- **并发保护**：创建修订必须声明 `basedOn`；若头部已被他人推进，返回 `409 revision_conflict`
  并附双方锚点差异（仅对方有/仅你有/同 ID 但内容改变）。
- **假设独立存储**：因果假设只保存依据与置信说明，不写回事件；一个事件可属于多个互相竞争的假设。

## 校时算法（piecewise-offset-v1）

1. 每个来源提交若干「观测钟面 → 参考绝对时间」锚点。
2. 墙钟锚点按参考时间展开到绝对日域：首锚点按 `floor` 定日偏移，后续锚点在
   「相对上一点流逝非负」的候选日期中取流逝最小者——跨午夜正常推进，时钟回卷的
   跳变表现为同夜内的短流逝，而不会被自动抹平。
3. 事件裸钟面值插入相邻锚点区间，段内对偏移做线性插值；外推额外加不确定度。
4. 不确定区间半宽 = 基础容差 1s + 段内观测流逝与参考流逝之差（漂移）/ 2，外推再加 2s。
   每行返回所用锚点 ID 集合，可逐行追溯。

## 排序与并列规则

按不确定区间**下界 → 上界 → 校正点 → eventKey** 稳定排序。随后从早到晚扫描：
区间（经传递闭包）互相重叠的事件归入同一并列组，UI 标记「并列」且**不暗示先后**；
不重叠的事件才承认明确先后。修订切换时原始时间、原始内容摘要列保持不变。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/events/batch` | NDJSON 批量导入，返回 accepted/rejected |
| POST | `/api/events/one` | 粘贴单条事件（失败也返回 202 + 原因） |
| GET  | `/api/timeline?revision=` | 修订时间线（含并列组、校正依据） |
| GET/POST | `/api/revisions` | 列出/创建修订（409 带锚点差异） |
| GET/POST | `/api/hypotheses` | 假设（依据 + 置信说明） |
| GET  | `/api/quarantine` | 隔离区 |
| GET  | `/api/export` | 证据包：事件摘要、原始字节归档、修订参数、假设、隔离区 + SHA-256 manifest |
| POST | `/api/replay` | 校验 manifest 并重放；幂等，重放后排序与来源链一致 |

状态保存在 SQLite（默认 `data/evidence.sqlite`，可用 `EVIDENCE_DB` 覆盖）。

## 测试

`npm test -- --run` 覆盖：坏行隔离、重复收据合并、内容冲突、分段校时（跨午夜/跳变）、
区间并列稳定排序、修订不可变与并发 409、导出 manifest 防篡改与重放等价性。
